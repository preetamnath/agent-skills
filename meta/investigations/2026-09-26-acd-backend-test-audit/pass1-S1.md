## Rule feedback

1. **Private state vs "resulting state".** prove-behavior Step 3: "Observation: Prefer observable outputs and resulting state." About 25 of the non-keeps here pair an observable event assert with an assert on private continuation or normalizer state (`cont._suppressed_tools`, `norm._usage`, `c.pending[...]`, `queue.qsize()`). "Resulting state" reads as permission for these. I treated private state as a change-detector when an observable assert in the same test already detects the defect, and as acceptable when nothing else can (leak checks). Proposed wording: "Prefer outputs and state a real caller can observe through the selected interface. Assert private state only when no caller-observable output can detect the named defect." Confidence 0.8.
2. **Literal pins of tuning constants.** Step 3: "A **change-detector test** fails after an internal refactor even though behavior remains correct." Changing a constant is not a refactor, so the definition does not clearly cover `test_opencode2_adapter.py:2473` (`_ONESHOT_GENERATE_ATTEMPTS == 3`, `== 5.0`), `:3268`, or `test_codex_adapter.py:9108-9110` (count asserts). A sibling test (`test_codex_adapter.py:3968`, `> 1.54`) shows the valid shape. Proposed addition: "A test of a tunable value asserts the requirement that value satisfies (a bound or ordering from its source), not the literal." Confidence 0.75.
3. **Resource leaks as harm.** Step 1: "Meaningful harm includes a broken user task, violated contract, corrupt data, weakened security or accessibility, or a repeated costly failure." Bounded-memory tests (`test_claude_adapter.py:1100` `_attribution`, `test_codex_adapter.py:8719` `_skills_probes`, `:2347` `token_usage`, tombstone caps `:2591` and `:6161`) can be checked only through private state, and the list does not say whether unbounded growth counts. I kept most of them and marked one Investigate. Proposed: add "unbounded resource growth on a long-lived object" to the harm list, or state that it does not count. Confidence 0.7.
4. **Tie-breaker at equal level.** "When another test detects the same defect, keep that check in the test at the lowest level that detects it." `test_scripted_adapter.py:127` and `test_adapters_base.py:653` are both unit-level, so the rule gives no winner. I kept the cross-leg parametrized one. Proposed: "At equal level, keep the check in the test that covers the widest contract (for example, a parametrized cross-implementation test)." Confidence 0.65.
5. **Pinned hazards and accepted risks.** Step 1 requires an "accepted source" but is silent on a documented accepted risk or a known hazard. `test_adapters_base.py:346` pins a hazard, and removing that hazard would be an improvement (I chose Remove). `test_claude_adapter.py:1802` and `:1915` pin accepted-risk or known-duplication behavior that a spec chose on purpose (I kept them). Proposed: "A documented accepted risk is an accepted source. A hazard whose removal would be an improvement is not." Confidence 0.6.
6. **Helper-derived expectations.** Step 1: "A **tautological test** derives its expected result from the same implementation logic". The RPC contract tests `test_codex_adapter.py:778`, `:813`, `:880` build `"config": _thread_config("high")` from the production helper. That part is tautological, but `:1979` pins the helper's output literally, so I kept them. Proposed: "An expectation computed by a production helper is acceptable only when another test pins that helper's output literally." Confidence 0.6.
7. **Wall-clock bounds.** Step 3 Races: "Do not rely on sleeps or scheduler timing." It does not say whether `elapsed < X` bound checks on timeouts count (`test_codex_adapter.py:1788`, `:4021`, `:7395`, `:7536`; `test_opencode2_adapter.py:3260`, `:3679`).
