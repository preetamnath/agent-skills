## Notable keeps

1. `test_jobs.py:48 test_spawned_task_is_strongly_referenced`: a genuine GC race (a frame-only future), confirmed by the same scratch experiment that disproved the hub twin. Keep this one; remove the hub twin.
2. `test_sessions_lifecycle.py test_every_sessions_topic_file_imports_the_harness_fixtures`: a source scan is the only possible observation (an unrequested fixture cannot be asserted from inside a test). It guards against the silent fallback to the non-blind fake.
3. `test_sessions_lifecycle.py test_sessions_py_names_no_provider`: a static provider-blindness contract. `ProviderBlindFakeAdapter` covers the unnamed-call half.
4. `test_sessions_queue.py test_d46_the_prompt_is_persisted_before_the_leg_is_called`: the ordering is the requirement (D-001-46). The yielding `send_hook` forces the race.
5. `test_sessions_queue.py test_two_duplicate_frames_arriving_together_cannot_interleave`: `gather` plus a yielding hook. The named mutation (an `await` in the dedupe window) is exactly what creates the interleaving.
6. `test_sessions_fork.py test_the_fork_count_frame_is_a_re_read_not_an_increment`: a single-tick `fork_hook` yield forces both forks past the check, and the docstring records the mutation proof in both directions.
7. `test_sessions_fork.py test_MESSAGE_EVENT_KINDS_mirrors_the_events_schema`: the backend half of a cross-file mirror pair; `test_ts_mirrors.py` owns the frontend half.
8. `test_hub.py test_broadcast_serializes_once_for_n_clients`: the identity (`is`) assertion is the requirement (one `json.dumps` per broadcast). Equality cannot detect the defect.
9. `test_sessions_lifecycle.py test_end_session_rejects_an_accepted_prompt_before_step_four`: seeds private `pending_prompts` deliberately, because no scheduler interleaving can reach the gap without a false pass. The reason is stated in the docstring.
10. `test_orchestration.py test_ac014_02_cap_is_enforced_under_concurrent_spawns` and `test_hub.py test_thread_patch_is_nullable_exactly_where_the_thread_row_is`: a yielding fake forces the cap race, and the cross-type nullability contract is not visible to mypy.

Also kept (listed because the rules push the other way): the wall-clock interrupt/heartbeat tests other than the two Repairs. Asyncio fires timers in deadline order, so `sleep(window+δ)` after a real-sleep watchdog is deterministic about wake order. The remaining risk is only a stall before the action the test must deliver inside the window.

## Rule feedback

1. **Races rule does not fit cooperative single-loop asyncio.** Quote: "Force the intended interleaving and prove readiness with an event, barrier, or queue. Do not rely on sleeps or scheduler timing." With in-loop fakes, a fixed yield count (`_settle()`, `sleep(0)`) and even real timers (deadline-ordered) are deterministic. The real failure mode is not flakiness. It is **silent vacuity**: a later production `await` means the absence assertion passes without the interleaving. The rule as written would flag well over 100 tests here (every `h.feed` uses `_settle`), so I flagged only absence assertions and lock-waiter ordering (lifecycle :1582, :1626, :2634, :2075, :2108; queue :477; actions :70). A parked lock waiter also has no public readiness event, so "prove readiness with an event" has no direct implementation. Proposed wording: "Prove readiness with an event, barrier, or queue. When the awaited state has no signal, assert that the contended state was reached. Before any absence assertion, assert that the background work finished." Confidence 0.75.
2. **Step 3 Interface conflicts with Races and with recovery-state setup.** Quote: "Use an existing stable production interface that a real caller uses at the selected level. Do not expose private code." About 40 kept tests force states through private seams: `_enter_recovery`, `_adopt`, `_retire`, `del _recovery_gates[...]`, `h.mgr._acquire = delayed_acquire`, `sess.pending_prompts.append`, and the shared `Harness.acquire` → `mgr._acquire`. No public interface can reach these interleavings. Read literally, the rule makes them Repair with no possible fix, so I kept them. Proposed wording: "When no public interface can reach the required state or interleaving, drive it through the narrowest internal seam and assert through public outputs." Confidence 0.70.
3. **The harm list is silent on performance-only requirements.** Quote: "Meaningful harm includes a broken user task, violated contract, corrupt data, weakened security or accessibility, or a repeated costly failure." Affected tests: write avoidance (lifecycle :1041), the boot sweep filter (boot :1488), the heartbeat skip (hub :737), query-plan/index tests (store `..._ride_the_partial_index`, `..._rides_the_thread_index`), and the `PRAGMA optimize` trace. I gave Remove at 0.40–0.45 to the three with no budget and kept the index tests. That split is my judgment, not the rule's. Proposal: "A performance requirement counts as meaningful harm only when an accepted source states a budget or a measured regression; otherwise choose no automated test." Confidence 0.70.
4. **Nothing requires that a reviewed test's assertions actually execute.** `test_acquire_closes_the_leg_when_the_caller_is_cancelled` has never run (no `asyncio.run`), but its docstring claims a negative control. Step 4 proof catches this only when someone reruns it, and the retain path does not require that. Proposal for the "retain" path: "Confirm the assertions execute (the natural-red or mutation proof, or a coverage line) before you retain a test." Confidence 0.60.
5. **Step 1 does not ask whether the named defect can actually happen.** Quote: "one plausible defect the evidence must detect". The hub GC test names a defect that cannot occur, because the queue future roots the task. A reviewer who trusts the docstring keeps it. Proposal: "Verify that the named defect can occur in the current code before crediting a test with detecting it." Confidence 0.55.
6. **Test-only production wrappers are addressed only on removal.** Quote: "Find any production export, flag, or wrapper that only this test uses, and remove it with the test." That applies only in the removal block, and Step 3's "Do not ... add a production interface only for testing" reads as forward-looking. `store.py` has three test-only aliases used by retained tests. Proposal: "When reviewing a test, also remove any production wrapper that only tests call, and call the real interface." Confidence 0.60.
7. **Literal and schema pins lack a rule.** The change-detector definition keys on "internal refactor". Changing a constant or adding a field is a contract change, so the definition does not settle literal pins (`_DEFAULT_IDLE_TIMEOUT_SECONDS == 1200`, `needs_attention == 30`, the exact `MessageSettled` fields). Order-sensitive field lists are a real refactor hazard. Proposal: "A literal pin is valid only when an accepted source states the value; compare as a set unless order is contractual." Confidence 0.60.
8. **Import-time or startup assertions are not listed as reusable evidence.** Quote: "reliable existing test, type check, static check, or contract check". `events.py:2513`'s import guard runs in every run but is none of these. Adding "import-time/startup assertion" would make `test_turn_payload_names_every_kinds_payload` a clean "reuse existing". Confidence 0.50.
9. **AC-witness tests: the repo convention and unique protection disagree.** The repo requires AC IDs in test names for searchability. `test_ac001_14_subagent_finals...` openly exists as an AC witness with no unique protection. The skill says remove it. The repo convention implies it is an AC coverage marker. Proposal: "An AC ID does not justify a test; put the ID on the test that detects that AC's defect." Confidence 0.55.
