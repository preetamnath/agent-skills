## Rule-caused errors

1. **Merge judged by the docstring's negative control, not by every branch the assertions run** (tests/test_app.py:3081, :7634). Rule: "Name the accepted source its assertions protect and what they check, not what its title claims." Pass-1 named what the assertions check but compared them only with the defect the docstring names. It missed the route's cancel-only branch (app.py:3845) and resume-failure reporting. Wording that would have prevented this: "Before you merge a test, list the production branches and outcomes its assertions reach. Confirm that the retained evidence runs and asserts each one."
2. **Repairs that delete an assertion without the before-remove checks** (tests/test_app.py:1388 list equality, :334 arity asserts, :5658 grep; tests/test_opencode2_adapter.py:3208 line 3270). The "Before you remove or merge a test" block applies to whole tests. Pass-1 deleted assertions that were the only guard of a contract. Wording: "Apply the before-remove checks to each assertion that a repair deletes, not only to whole tests."
3. **Non-vacuity and precondition asserts read as change-detectors** (tests/test_codex_wait_outcomes.py:394 `turn_done == 2`, tests/test_slack_bridge.py:5616 decode equality). Rule: "A change-detector test fails after an internal refactor even though behavior remains correct." Pass-1 applied it to observable behavior changes and to guards that prove the scenario reached the defect path. Wording: "An assertion that proves the scenario reached the guarded path is not a change-detector. Weaken it only when a replacement proves the same reach."
4. **Unbounded-state harm is undefined** (tests/test_claude_adapter.py:1100). Rule: "Meaningful harm includes a broken user task, violated contract, corrupt data, weakened security or accessibility, or a repeated costly failure." The Investigate verdict was a rule question, not a source question. Wording: "Growth that is bounded per operation and never read is not meaningful harm. Unbounded growth on a long-lived object is meaningful harm."
5. **Private helper as interface is decided differently between shards** (S1 Repair: tests/test_codex_adapter.py:7297 `_narrow`, tests/test_opencode2_transport.py:400 `_read_handshake`; S3 kept about 70 such tests). Rule: "Use an existing stable production interface that a real caller uses at the selected level." "Real caller" can mean a production caller of the private function or an external caller of the module. Wording: "At unit level, a module-private function is an acceptable interface when it alone owns the rule. Assert on private state only when no caller-observable output detects the defect."
6. **Bound derived without the mechanism** (tests/test_opencode2_adapter.py:2473). Pass-1 proposed `(ATTEMPTS - 1) * DELAY >= 6.4`, but the ladder sleeps before each attempt. No rule covers tuning constants, so the reviewer made up a formula. Wording: "A test of a tunable value asserts the bound its source states, derived from the code's actual schedule, not from the literal."
7. **Uniqueness judged against a harness constant** (tests/test_app.py:828, :6023). The retained tests send `headers=AUTH`, and `AUTH = {}`. They show tokenlessness only while the constant stays empty. The rules do not say whether to fix the harness first. Wording: "When a harness constant stands in for the protected behavior, make the retained test state it explicitly before you merge."
