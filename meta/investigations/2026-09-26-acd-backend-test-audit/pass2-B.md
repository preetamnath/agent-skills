## Rule-caused errors

1. **Harm list read as closed.** Rule, Step 1: "Meaningful harm includes a broken user task, violated contract, corrupt data, weakened security or accessibility, or a repeated costly failure." Pass-1 treated this as a closed list and gave the same verdict to constant-cost perf (lifecycle:1041, hub:737) and to unbounded startup latency (boot:1488). Wording that would have prevented it: "The list is illustrative. Resource use that grows without bound on a user or startup path is meaningful harm; a constant per-operation cost is not, unless an accepted source sets a budget."
2. **Spec-stated literals called change-detectors.** Rule, Step 3: "A change-detector test fails after an internal refactor even though behavior remains correct." Pass-1 did not check whether a spec states the literal, and flagged config:57 (AC-004-12 says Opus/medium), config:114 (spec 044 says 200/600), and schedules_mirror (D-013-29 locks the vocabulary). Wording: "Before you call a literal pin a change-detector, check the accepted source. A value the source states is the requirement, and changing it is a behavior change, not a refactor."
3. **Retained evidence named without checking the input path.** Rule, "Before you remove or merge a test": "Name the evidence that will still detect its defect in the normal verification command or CI." Pass-1 named guards that do not reach the same input: ttlcache:114 (the guards pass `max_entries=8`, never the default), terminals:728 (retained cap tests use one folder), and queue:1157 (store tests cannot see a sessions-layer revert). Wording: "Confirm the retained evidence exercises the same input and code path (defaults, calling layer), not only the same named mutation."
4. **"Lowest level" applied to a defect in a different layer.** Rule: "When another test detects the same defect, keep that check in the test at the lowest level that detects it." At queue:1157 the historical bug was in the calling layer (the sweep read a tail), so the lower-level store test detects a different defect. Wording: "A defect in the calling layer is a different defect from one in the callee, even when both are named by the same mutation."
5. **Race repairs that do not check existing serialization.** Rule, Step 3 Races: "Force the intended interleaving and prove readiness with an event, barrier, or queue." At lifecycle:2075, pass-1 applied this rule, but `respond` already holds the chat lock that recovery needs, so no readiness signal can make the named defect detectable. Wording: "Before you repair a race test, confirm that no other guard (a lock or a gate) already serializes the interleaving; if one does, name the defect the test can still detect."
6. **"Merge" used for parametrize consolidation.** Brief verdict table: "Merge | Duplicates another test's protection for the same defect." push:220, digest:412, browsers:932, and the acd refusal set are separate cases (different set members or commands) and must keep every case.
